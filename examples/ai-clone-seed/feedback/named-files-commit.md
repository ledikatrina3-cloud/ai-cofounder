---
name: named-files-commit
description: `git add` только поимённо. Никогда `git add -A`, `git add .`, `git commit -a`.
type: feedback
---

При коммите явно перечисляем файлы:
`git add path/file1.ts path/file2.md` → `git commit -m "..."`.
Никогда `git add -A` / `git add .` / `git commit -a`.

**Why:** параллельные routine-сотрудники AI-кофаундера могут иметь
свой WIP в репо. `git add -A` затянет в коммит чужие незаконченные
файлы. Прецедент: при работе с агентами один раз закоммитил незаконченную
ветку параллельного процесса — пришлось разбираться через `git reflog`.

Плюс: явная отвественность. Если случайно положил `.env.local` в add —
он сразу виден глазам перед commit. С `-A` уйдёт молча.

**How to apply:**
- Каждый commit-flow: явный список файлов, прочитал что коммитишь, коммит.
- Если файлов >10 — это намёк что фича слишком большая, стоит разбить.
- В CI / hooks нельзя `git add -A` ни при каких условиях.
- Исключение: первоначальный коммит нового проекта. Один раз.
