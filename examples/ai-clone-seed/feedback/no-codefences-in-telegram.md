---
name: no-codefences-in-telegram
description: В Telegram-сообщениях НЕ оборачивать финальный блок в \`\`\`...\`\`\`. URL внутри code-block некликабельные.
type: feedback
---

Когда инструктируем routine-агента как формат финального отчёта в
Telegram — НЕ просим обернуть блок в \`\`\`...\`\`\`. Только построчные
ключи (`URL:`, `STATUS:`, `H1:` и т.д.).

**Why:** Telegram Markdown v1 (наш `parse_mode: 'Markdown'`) рендерит
\`\`\`...\`\`\` как monospace code-block. Внутри такого блока URL'ы НЕ
автоконвертируются в кликабельные ссылки. Фаундер получает «ссылку»
плоским моноширинным текстом, нельзя ткнуть — нужно копипастить.

Прецедент с маркетинг-контент routine: я инструктировал
агента финальным блоком вида:
````
\`\`\`
🟢 / 🟡 / 🔴 ...
URL: https://...
\`\`\`
````
Агент послушал буквально. URL в Telegram пришёл некликабельным. Плюс
Markdown упал на parse-error из-за длинного `*...*` в подстановке
`description`.

**How to apply:**
- В routine.body инструкция про финал = «выведи строки с ключами», не
  «выведи блок в \`\`\`».
- Серверный страховка: `src/report/render.ts:stripCodeFences()` —
  автоматически снимает обрамляющие \`\`\` если они всё-таки попали.
- Если нужно показать многострочную команду в сообщении — лучше один
  бэктик `\`...\`` (inline code), либо плоский текст с отступом 4 пробела.
