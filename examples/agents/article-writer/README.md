# Article Writer

Флагманский пример-агент: самодостаточная контент-фабрика. Из источника тем
(список, прошлая статья, CSV, заметка) делает одну вирусную статью и проводит её
через полный конвейер: выбор угла, вирусный скоринг, H1 + lead, структура,
глубокая переработка, обложка и многоступенчатый QA (анти-AI, тон, уникальность,
конфиденциальность).

## Что на выходе (по умолчанию)

Пишет в `./content/`, **без API-ключей и без БД** (офлайн, кроме стадии 2 research - запрос к бесплатному публичному эндпоинту DuckDuckGo):

- `content/<slug>.md` - master-draft;
- `content/<slug>.html` - paste-ready HTML;
- обложка SVG по умолчанию (PNG, если установлена опциональная зависимость `sharp`; простая типографика через скилл `cover-design`);
- `content/<slug>.checklist.md` - физический чек-лист прогона.

## Какие скиллы использует

Только shared-скиллы из библиотеки репозитория:

- `article-writing` - master-draft и self-edit;
- `research-serp` - SERP-проверка угла (стадия 2);
- `seo-audit` - структурный SEO-аудит драфта;
- `cover-design` - типографская обложка (PNG/SVG, без AI-картинок).

## Как включить

1. Запусти `/setup` и выбери article-writer - он копирует папку в `agents/` и
   ставит `enabled: true`. Либо скопируй папку вручную в `agents/article-writer/`
   и поставь `enabled: true` ТАМ. Никогда не правь копию под `examples/`.
2. Запусти руками (`schedule: manual`). Агент работает автономно сверху вниз и
   останавливается только на gate-условиях.

Дефолт безопасен: ни БД, ни API-ключей, ни image-gen-ключа. Единственный сетевой
вызов - стадия 2 research, бесплатный публичный эндпоинт DuckDuckGo (без ключа).
Всё складывается в `./content/`.

## Как включить внешнюю публикацию (опционально)

По умолчанию выключена. Чтобы публиковать на внешнюю платформу:

```
cp target.yml.example target.yml
```

затем заполни `target.yml` под свой проект (cwd target-репозитория, allowlist
скиллов, имя publish-токена в `syncEnv`). Какой адаптер запускать - решает сам
target-репозиторий, не этот файл: публикатор pluggable, детали платформы живут в
адаптере на стороне target-репозитория, ядро агента их не знает. Пока файла
`target.yml` нет - публикация остаётся выключенной.

## Файлы

- `AGENT.md` - манифест (frontmatter + описание);
- `prompt.md` - полная методика контент-фабрики (инструкции агента);
- `rules.md` - guardrails (заголовки, ссылки, анти-AI, конфиденциальность);
- `permissions.yml` - инструменты (реальные имена из `tool-registry.ts`);
- `target.yml.example` - пример opt-in внешней публикации;
- `content/` - каталог вывода по умолчанию.
