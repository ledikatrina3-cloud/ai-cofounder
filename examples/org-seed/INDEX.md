# org — корпоративный второй мозг (бизнес-слой)

«Что мы делаем». Знания о проекте AI-кофаундера как продукта и как
рабочей инфраструктуры. Эта папка **едет с проектом**; если завтра
проект передаётся партнёру, она едет тоже.

Не путать с [`ai-clone/`](../ai-clone/INDEX.md) — там «как я решаю» (про фаундера лично).

**Правило роутинга:** агент сначала читает [`ai-clone/INDEX`](../ai-clone/INDEX.md)
(чтобы понять как звучу) → потом этот INDEX (чтобы понять что мы делаем) →
потом ныряет в нужный конкретный файл по таблицам выше. Это just-in-time
контекст: указатели вместо данных.

## Что НЕ кладём сюда

- **Сырая переписка из Telegram без обработки** — выжимай, формулируй, тогда клади.
- **Технические детали стека / конкретные команды** — это
  [`infrastructure/`](../infrastructure/) или [`CLAUDE.md`](../CLAUDE.md).
- **Динамические цифры** (выручка, потоки, оплаты) — это `live-metrics.md`
  через маркер LIVE (TODO: пока такого файла нет, цифры из БД руками).
- **Скриншоты, картинки** — увеличивают вес, не парсятся текстовой моделью.
- **Секреты, токены, пароли** — Keychain, не файлы (см.
  [[../ai-clone/feedback/no-env-read]]).
- **Личные правила фаундера** — это в [[../ai-clone/feedback]], не сюда.
  Здесь только то, что **едет с проектом**, не с фаундером.

## Размер и обновление

- Каждый файл — фокусированный на одной теме. Длинных «всё про всё» файлов
  не делаем. Если файл >200 строк — пора разбивать.
- Обновляется по принципу [[../ai-clone/feedback/retro-after-feature]]: после
  каждого крупного изменения системы — одна строка в нужный файл.
- Главный live-файл — [[company/stage]]. Сверяться после каждого закрытия
  milestone'а.
