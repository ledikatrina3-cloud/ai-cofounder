# ТЗ на cover (обложки) для spoke-статей

Методология для всех cover, которые AI-агент генерирует под публикации vc.ru, Habr, Reddit, LinkedIn. Применяется в `skill build-vc-spoke` Этап 7 (cover generation).

## Цель cover

**Заставить читателя ленты остановить скролл за < 1 секунду.** Cover — это hook, не визитка бренда. Если читатель не зацепился взглядом в первую секунду — он пролистал.

Cover работает в трёх контекстах:
1. **Карточка поста в ленте** (vc.ru/ai, Habr.com/feed) — миниатюра 600×400 или меньше
2. **Заглавная картинка статьи** — после клика, 1920×1080 в полную ширину
3. **OG-превью в Telegram/Twitter/Slack** — когда кто-то делится ссылкой

В каждом из трёх должно работать. Особенно (1) — там 90% касаний.

## Что ДОЛЖНО быть на cover

1. **Заголовок крупным шрифтом** — занимает 40-60% высоты, читается с расстояния iPhone-в-руке
   - Размер: 140-180px (для 1920×1080 canvas)
   - Шрифт: жирный sans-serif (Plus Jakarta Sans, Inter, Manrope)
   - Line-height: 0.95-1.05 (плотно)
   - Letter-spacing: -0.03em (чуть сжатая для visual weight)
   - Цвет: контрастный к фону (`#ede9e3` на тёмном)
   - **Акцент-слова** выделены вторым цветом или другим шрифтом (italic serif вроде Instrument Serif)

2. **Один визуальный артефакт** — НЕ фоновая текстура, а конкретный объект
   - Связан с темой статьи (про hooks → JSON-сниппет; про token → ASCII-схема pipeline; про migrations → diff-блок)
   - Расположен сбоку или подложен под текст
   - 30-50% площади
   - Не отвлекает от title, **подкрепляет** его

## Что НЕ должно быть на cover

- ❌ **Лого/брендинг** — ни названия проекта, ни «Claude Code · Hooks», ни упоминаний сайта
- ❌ **URL-плашки** (`acme.example.com · vc.ru/...`) — это шум, никто не читает
- ❌ **Стрелочки и иконки CTA** — это не лендинг, читатель уже в ленте
- ❌ **Subline-описания** («Готовые JSON-сниппеты · 30 секунд на каждый») — это уже в первом параграфе статьи, на cover не нужны
- ❌ **Stock-фото людей у ноутбука** — мёртвый sign, никто не задерживается
- ❌ **AI-генеренные фотореалистичные сцены** — в технической нише выглядят дёшево

Чем чище cover, тем сильнее ловит взгляд. Минимализм > украшательство.

## Палитра

Тёмная (default для tech-статей):
- Фон: `#141413` (почти-чёрный)
- Текст основной: `#ede9e3` (тёплый off-white)
- Акцент: `#d97757` (тёрракот — корпоративный акцент проекта)
- Сетка / графика: `rgba(217,119,87,0.05–0.15)` (тонко-оранжевый)
- Subtle glow: `radial-gradient` за артефактом (рост восприятия глубины)

Светлая (для статей про продукт-менеджмент / soft skills):
- Фон: `#f5f1ea`
- Текст: `#1c1b1a`
- Акцент: `#d97757`

Не использовать: ярко-синий (тех-клише), зелёный (success-toast вайб), фиолетовый (AI-стартап-клише).

## Визуальный артефакт — типы под топику

| Тип статьи | Артефакт |
|---|---|
| Tooling (hooks, MCP, settings.json) | JSON-сниппет в моноспейс-шрифте, 4-8 строк, syntax-highlighted |
| Architecture / patterns | ASCII-схема blocks ↔ arrows (3-5 узлов) |
| Database / migrations | Diff-блок (`-`/`+` в две колонки), 4-6 строк |
| Debugging / postmortem | Stacktrace или log-snippet с подчёркнутым ключевым словом |
| Process / methodology | Простая геометрия: 3 концентрических круга, граф, timeline |
| Personal / opinion | Без артефакта, только title в полный экран с акцентом на одно слово italic |

Артефакт **никогда не объясняет статью** — он намёк, символ, hook. «Прочитал бы целиком чтобы понять что это» — плохой артефакт.

## Композиция

```
┌──────────────────────────────────────┐
│                                      │
│   [Title крупно, 2-3 строки]         │
│   с акцентом на одно слово           │
│                                      │
│                                      │
│              [Артефакт]              │
│         справа или внизу             │
│                                      │
└──────────────────────────────────────┘
```

Соотношение: title 55%, артефакт 35%, отступы 10%. Падинг минимум 120px от краёв.

## Технические параметры

- Размер: **1920×1080** (16:9)
- Формат: PNG (для прозрачности и резкости), вес 100-300KB
- DPI: 72 (web)
- Шрифты загружаются из Google Fonts (`Plus Jakarta Sans`, `Instrument Serif`, `JetBrains Mono` для кода)
- Рендеринг: headless Chromium через patchright, screenshot 1920×1080

## Где формируется и где живёт

1. **Генерация:** skill `build-vc-spoke` Этап 7 (cover) — берёт **финальный** title (после всех ревизий), подставляет в template `/tmp/vc-spoke-<slug>/cover.html`, рендерит через patchright → `/tmp/vc-spoke-<slug>/cover.png`.
2. **При смене title после генерации:** cover **обязан перегенериться**. Хранить рядом `cover.title.txt` с тем title, под который рисовался. Перед публикацией: `cover.title.txt == frontmatter.title`? Иначе regenerate.
3. **Хранение:** `/tmp/vc-spoke-<slug>/` (ephemeral). Долговременная история — в downstream-проекте `content/vc-drafts/<slug>/cover.png` (рядом с draft.md).
4. **Загрузка:** publisher (`scripts/vc-publish-api.ts`) → `POST /v2.1/uploader/upload` → uuid → cover-блок типа `media` первым в entry.

## Адаптация под платформы

- **vc.ru:** дефолт описанный выше
- **Habr:** light палитра (Habr-аудитория чаще тёмная тема в браузере, но cover лучше выделить контрастом)
- **Reddit:** тёмная палитра, артефакт обязательно (Reddit без артефакта = "spam-promotional" вайб)
- **LinkedIn:** light палитра, без italic-акцентов (LinkedIn — formal), артефакт максимально простой

## Анти-примеры (что НЕ делать)

1. Cover для статьи `getting-started-with-hooks` (v1): сверху лого проекта + eyebrow "CLAUDE CODE · HOOKS", title 4 строки в полстраницы, снизу "acme.example.com · vc.ru/<handle>" + стрелочка. **Шум 30% площади, артефакта нет.** → отбраковано фаундером.

## Чек-лист перед публикацией

- [ ] Заголовок на cover **точно совпадает** с frontmatter.title (включая знаки препинания)
- [ ] Нет логотипов, URL-плашек, CTA-стрелочек, eyebrow-категорий
- [ ] Есть один визуальный артефакт (или title в полный экран с акцентом)
- [ ] Контраст title к фону ≥ 7:1 (WCAG AA для крупного текста)
- [ ] Размер файла 100-300KB
- [ ] Открыл на iPhone — title читается без масштабирования
