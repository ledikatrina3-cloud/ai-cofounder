# Артемий Миллер шаг 3: Контекст-инжиниринг

## Зачем

Контекст-инжиниринг - главная идея Миллера: не писать длинный промпт каждый раз, а разложить знания в файлы так, чтобы Codex сам нашёл нужное. В версии под Codex это `AGENTS.md` + `business/` + `ai-clone/` + `mastery/` + `plans/` + `memory/`.

## 5 слоёв контекста

1. `AGENTS.md` - правила проекта и навигация.
2. `ai-clone/` - как ты думаешь, пишешь, принимаешь решения.
3. `business/` - второй мозг проекта: продукт, аудитория, экономика, маркетинг.
4. `mastery/` - методы авторов и практиков.
5. `plans/` и `memory/` - текущие фазы, решения, правила, ретроспективы.

## Промпт 1: ai-clone

```text
Создай в корне проекта папку ai-clone/ - цифровую проекцию меня для Codex.

Структура:
ai-clone/
├── INDEX.md
├── role.md
├── identity/{vision.md, values.md, mission.md, biography.md}
├── voice/{tone.md, vocabulary.md, stop-words.md}
├── thinking/{mental-models.md}
├── principles/{business.md, product.md, code.md}
├── feedback/README.md
├── style/telegram-format.md
└── reference/README.md

Создай файлы-заглушки с коротким описанием, что туда писать.
В feedback/README.md укажи формат: Правило / Почему / Как применить.

После создания проведи меня через интервью по одному вопросу за раз.
После каждого моего ответа записывай в нужный файл и только потом задавай следующий вопрос.
```

## Промпт 2: business

```text
Создай в корне проекта папку business/ - второй мозг бизнеса.

Структура:
business/
├── INDEX.md
├── products/
├── audience/
├── economics/
├── marketing/
├── goals/
├── assets/
├── research/
├── methods/
├── raw/
└── life-metrics.md

В каждой подпапке создай README.md с пометкой "заполнить интервью-промтом".
В business/INDEX.md сделай карту папки и ссылки на разделы.
В life-metrics.md создай заглушку для будущих живых цифр.

Дальше проведи интервью по блокам:
1. продукты
2. аудитория
3. экономика
4. маркетинг
5. цели
6. активы и доказательства
7. исследования и сырьё

Правила:
- спрашивай по одному вопросу
- если данных мало, создай файл "заполнить позже"
- не выдумывай
- персональные данные клиентов не коммить, складывай только обезличенно
```

## Промпт 3: mastery

```text
Создай или обнови папку mastery/.

Это не библиотека пересказов, а личный совет директоров: методы лучших практиков, которые Codex может применять в проекте.

Правила:
1. Один автор или методологическая линия = отдельный файл или серия файлов.
2. Писать только применимое: что делать, как делать, когда применять.
3. Не переносить книги и курсы целиком.
4. Если есть транскрипт выступления, выделять методы и алгоритмы.

Для текущего проекта найди 3 области мастерства, которые помогут первой фиче, и предложи структуру mastery/.
Ничего не заполняй без моего подтверждения.
```

## Промпт 4: проверить контекст

```text
Прочитай:
- AGENTS.md
- ai-clone/INDEX.md
- business/INDEX.md
- mastery/INDEX.md
- plans/README.md, если есть

Проверь, может ли новый Codex-чат понять проект без моего длинного объяснения.

Ответь таблицей:
| Контекст | Файл | Достаточно? | Что добавить |

Потом предложи 5 правок, которые сильнее всего улучшат контекст-инжиниринг.
Не правь файлы, пока я не скажу "давай".
```

## Готовность

Шаг готов, когда короткий запрос вроде "сделай лендинг по методу" может провалиться по ссылкам в нужные файлы, а не требовать простыню контекста в чате.
