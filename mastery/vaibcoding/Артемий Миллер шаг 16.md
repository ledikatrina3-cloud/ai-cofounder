# Артемий Миллер шаг 16: Commit, deploy и ретроспектива

## Зачем

Фича не закончена, пока она не зафиксирована, проверена, при необходимости выложена и описана в ретроспективе. У Миллера результат доводится до жизни: сначала safety gate, потом commit, потом deploy, потом разбор цикла. Всё, что относится к обновлению бизнес-базы и метод-файлам, уходит в следующие шаги.

## Commit-ритуал под Codex

```text
Подготовь фичу к коммиту.

Сделай по порядку:
1. Проверь статус файлов.
2. Покажи список изменённых файлов.
3. Запусти релевантные проверки из AGENTS.md или package.json.
4. Покажи краткий diff по смыслу.
5. Проверь, что security-шаг пройден или явно отложен.
6. Предложи commit message.
7. Не делай git add . и git add -A.
8. Добавляй файлы только поимённо.
9. Не пушь без моей явной команды.

Если проверки падают, не коммить. Сначала дай план исправления.
```

## Deploy-ритуал

```text
Подготовь деплой, но не запускай его без моей явной команды.

Проверь:
- где деплоится проект
- какие ENV-переменные нужны на проде
- есть ли .env.example
- не попали ли секреты в git
- какая команда build
- какая команда deploy
- есть ли миграции базы
- есть ли backup
- есть ли rollback-план

Выдай:
1. чек-лист перед деплоем
2. команду деплоя
3. что проверить после деплоя
4. что делать, если деплой упал

Жди моей команды "деплой".
```

## Постдеплойная проверка

```text
Деплой завершён.

Проверь продукт как пользователь:
1. Основной сценарий работает.
2. Новая фича видна.
3. Старый ключевой сценарий не сломан.
4. Ошибки наружу не показывают stack trace.
5. Логи не содержат секретов или личных данных.
6. Метрика успеха фичи может быть измерена.

Дай результат:
- OK
- починить сейчас
- отложить
```

## Ретроспектива

```text
Заполни retrospectives/YYYY-MM-DD_HH-MM_<описание>.md по TEMPLATE.md.

Используй факты:
- план из plans/
- список изменённых файлов
- проверки
- security-выводы
- ошибки, которые нашли
- решения, которые приняли
- что отложили

Добавь раздел "В долгую память":
- какие правила добавить в memory/
- что обновить в AGENTS.md
- какие факты отнести в business/
- нужен ли отдельный метод-файл на следующем шаге

Не обновляй business/ и methods/ внутри этой задачи. Только зафиксируй, что туда нужно перенести.
```

## Готовность

Шаг готов, когда фича не просто "написана", а проверена, безопасно зафиксирована, при необходимости выложена, проверена после деплоя и описана в ретро.
