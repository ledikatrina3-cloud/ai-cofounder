# Артемий Миллер шаг 19: Codex-инструменты и автоматизации

## Зачем

В исходной методологии много инструментального слоя: браузер, внешние сервисы, агенты, триггеры, повторяемые сценарии. В Codex это нужно переводить не дословно, а по функции. Цель не "поставить больше инструментов", а дать каждому повторяемому действию правильную среду.

Инструмент выбирается после понимания задачи: visual check, приватные данные, GitHub, Notion, автоматизация, отдельный тред, skill, security scan.

## Карта соответствий под Codex

1. Визуальная проверка сайта или приложения - in-app browser, Playwright, скриншоты.
2. Доступ к рабочим знаниям - connectors/MCP, если они подключены в среде.
3. Повторяемый рабочий ритуал - skill или метод-файл.
4. Долгий мониторинг - automation/reminder, если инструмент доступен.
5. Независимые ветки работы - отдельные Codex-треды или worktree.
6. Проверка безопасности - security scan или ручной security-чеклист.
7. Создание артефактов - method files в `business/methods/`.

## Промпт 1: проверить доступные инструменты

```text
Проверь, какие Codex-инструменты доступны в этой среде для моей задачи.

Задача:
<что нужно сделать>

Не подключай ничего сам.
Сначала дай карту:
1. Какие инструменты доступны.
2. Для чего каждый подходит.
3. Что лучше сделать обычными файлами.
4. Где нужен мой явный approval.
5. Какие инструменты не видны в этой среде, поэтому их нельзя обещать.

После карты предложи один минимальный маршрут.
```

## Промпт 2: подобрать инструмент под задачу

```text
Подбери инструмент под задачу:
<описание задачи>

Выбирай по правилу:
- если нужно изменить код, работай в репозитории
- если нужно проверить UI, используй браузер/Playwright
- если нужно найти знания в Notion/GitHub, используй connector, если он доступен
- если действие повторилось 2-3 раза, предложи method-file или skill
- если задача независимая, предложи отдельный тред
- если нужен регулярный контроль, предложи automation

Не используй инструмент ради инструмента.
Дай: инструмент | зачем | риск | что спросить у меня.
```

## Промпт 3: создать skill только после повторения

```text
Создай skill или метод только если действие уже повторилось 2-3 раза.

Сначала проверь:
1. Что именно повторяется.
2. Какие входы всегда нужны.
3. Какие шаги стабильны.
4. Какие ошибки постоянно возникают.
5. Где хранить результат: skill или business/methods/.

Если это рабочий ритуал Codex - предложи skill.
Если это бизнес-артефакт - предложи method-file.
Если повторения нет - не создавай ничего.
```

## Промпт 4: разнести работу по тредам

```text
Разбей задачу на Codex-треды только если части независимы.

Задача:
<описание>

Дай:
1. Какие части можно делать параллельно.
2. Какие зависят друг от друга.
3. Какой общий источник правды читать каждому треду.
4. Какой deliverable должен вернуть каждый тред.
5. Как собрать результаты обратно.

Не создавай новые треды без моей команды.
```

## Готовность

Шаг готов, когда для повторяемых действий выбран правильный Codex-механизм: файл, method, skill, connector, браузер, automation или отдельный тред. Ничего не обещано, если инструмент недоступен в текущей среде.
