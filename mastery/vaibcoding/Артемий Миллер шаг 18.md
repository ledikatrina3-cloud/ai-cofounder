# Артемий Миллер шаг 18: Метод-файлы и артефакты

## Зачем

У Миллера всё, что повторилось 2-3 раза, превращается в методологию. Лендинг, презентация, пост, рассылка, питч, отчёт, onboarding, коммерческое предложение - это не разовый текст, а завод по сборке артефакта. Сначала метод, потом сборка.

Метод-файл нужен, чтобы Codex не угадывал стиль, структуру и смысл каждый раз заново. Он читает метод, читает источники по wikilinks и собирает новый артефакт по твоей системе.

## Когда применять

1. Ты второй или третий раз делаешь один и тот же тип артефакта.
2. Codex каждый раз задаёт одни и те же вопросы.
3. Артефакт должен держать твой тон, УТП и продуктовые смыслы.
4. Нужно передать сборку подрядчику или другому треду.
5. Есть `business/marketing/utp.md` и источники смыслов из отзывов конкурентов.

## Промпт 1: создать метод-файл

```text
В business/ создай раздел methods/, если его нет.

Создай метод-файл для повторяющегося артефакта.
Артефакт: <лендинг / презентация / рассылка / пост / питч / отчёт / onboarding>

Задача: собрать всё, что я уже знаю про то, как этот артефакт у меня устроен, в один метод-файл.
Так, чтобы в следующий раз я сказала "собери X по методу", и ты повторил мой стиль без вопросов.

Сначала прочитай:
- business/marketing/utp.md
- business/research/pain-to-meaning.md, если есть
- business/research/love-to-positioning.md, если есть
- business/audience/
- business/products/
- business/assets/ или brand/, если есть
- прошлые артефакты этого типа в репозитории
- idea/ и architecture/, если они релевантны

Потом задай мне 5-7 вопросов по одному:
1. Какая структура у артефакта устоялась?
2. Какие смысловые блоки обязательны?
3. Какой тон голоса использовать и чего избегать?
4. Какие типовые ошибки AI делает без метода?
5. Какие источники смыслов использовать?
6. Какие триггеры и стоп-слова работают?
7. Какой технический формат нужен?

После интервью создай business/methods/<артефакт>.md.
Не собирай сам артефакт, пока я не скажу.
```

## Шаблон метода

```text
# Метод: <артефакт>

## Когда применять

## Источники контекста
Wikilinks на УТП, аудиторию, продукт, прошлые примеры.

## Пошаговая сборка
Шаг 1.
Шаг 2.
Шаг 3.

## Обязательные блоки

## Запреты

## Тон и стиль

## Проверка качества

## Лог применений
Дата | Что собрали | Что сработало | Что переделали
```

## Промпт 2: собрать артефакт по методу

```text
Собери для меня <артефакт> по готовому методу.

Шаги:
1. Прочитай business/methods/<артефакт>.md.
2. По wikilinks из метода прочитай источники: бренд, аудиторию, УТП, продукт, боли.
3. Спроси меня по одному вопросу:
   - что конкретно собираем сейчас
   - для какого продукта
   - под какую цель
   - какие 3-5 смыслов обязательны
4. Собери черновик в формате из метода.
5. Покажи результат.
6. После моего "ок" добавь в лог метода запись: дата, что собрали, что сработало, что переделали.

Не запускай сборку до моих ответов.
```

## Промпт 3: улучшить метод после применения

```text
Мы применили метод business/methods/<артефакт>.md.

Сравни:
- исходный метод
- получившийся артефакт
- мои правки
- что пришлось объяснять вручную

Обнови метод так, чтобы в следующий раз эти объяснения уже были внутри.
Не меняй стиль ради красоты. Меняй только то, что реально сэкономит следующий цикл.
```

## Готовность

Шаг готов, когда повторяющийся артефакт имеет метод-файл, источники через wikilinks, пошаговую сборку, запреты, критерии качества и лог применений.
