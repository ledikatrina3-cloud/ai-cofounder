# Артемий Миллер шаг 1: Снаряд продукта

## Зачем

У Миллера старт не с кода, а со "снаряда": один проект, один сегмент, одна метрика, одна первая фаза. Это защита от расползания, когда AI быстро пишет много кода, но непонятно для кого и зачем.

В Codex этот шаг нужен до любых правок. Сначала создается `instructions.md` или отдельный brief, потом Codex задает вопросы и фиксирует решение в файлах.

## Что сделать

1. Выбрать один продукт, который реально можно довести до демо.
2. Сузить аудиторию до одного сегмента.
3. Выбрать одну метрику успеха.
4. Описать первую фазу, которую можно показать живому человеку.
5. Запретить Codex начинать код до подтверждения снаряда.

## Промпт для Codex

```text
Создай в корне проекта файл instructions.md.

Мне нужно сформулировать "снаряд" проекта по методологии Артемия Миллера:
- один проект
- один сегмент клиента
- одна ключевая проблема
- одна метрика успеха
- одна первая фаза, которую можно довести до демо

Действуй так:
1. Сначала задай мне вопросы по одному, не списком.
2. Если я отвечаю сумбурно, структурируй ответ сам.
3. Если я говорю "на твое усмотрение", прими решение и объясни почему.
4. После каждого ответа обновляй instructions.md.
5. Не пиши код и не создавай продукт, пока не будет готов финальный снаряд.

Формат instructions.md:
# Снаряд проекта

## Идея в одном предложении
## Для кого
## Какая боль
## Первая метрика успеха
## Первая фаза
## Что не делаем сейчас
## Риски
## Следующий шаг

Начни с первого вопроса: что я хочу создать?
```

## Как понять, что шаг готов

- Есть `instructions.md`.
- Идея звучит в одном предложении.
- Есть первая фаза, которую можно закончить за короткий цикл.
- Есть список "что не делаем сейчас".

## Когда переходить дальше

Переходи к шагу 2, когда можешь сказать: "я понимаю, кому, зачем и какой первый кусок продукта делаю".
