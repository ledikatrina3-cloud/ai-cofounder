# Артемий Миллер шаг 20: Мобильный путь Expo

## Зачем

Мобильное приложение - это отдельная ветка методологии, а не обязательный шаг для каждого продукта. Её включают, когда продукту реально нужен телефон: камера, пуши, геолокация, офлайн, быстрый ежедневный вход, привычка пользователя. Если этого нет, сначала делай веб.

Формула Миллера для мобильного старта: один экран, одна кнопка, одно действие. Не "сразу приложение", а минимальный мобильный барьер, который доказывает, что продукту нужен телефон.

## Когда применять

1. Пользователь должен делать действие на ходу.
2. Нужны push-уведомления.
3. Нужны камера, файлы, геолокация или нативные возможности.
4. Web UX явно мешает основному сценарию.
5. Есть уже проверенный смысл продукта и первая фича.

Не применять, если мобильность нужна только "чтобы было приложение".

## Промпт 1: решить, нужен ли mobile

```text
Проверь, нужна ли моему продукту мобильная ветка.

Прочитай:
- business/INDEX.md
- business/life-metrics.md, если есть
- idea/
- architecture/
- plans/

Оцени:
1. Какие сценарии требуют телефона.
2. Какие можно закрыть вебом.
3. Есть ли причина для push, camera, files, geolocation или offline.
4. Какая одна мобильная фича докажет ценность.
5. Что нельзя делать в первой мобильной версии.

Вывод:
- mobile нужен сейчас
- mobile отложить
- mobile не нужен

Не создавай проект без моего "ок".
```

## Промпт 2: план Expo-ветки

```text
Мне нужна мобильная версия по методологии Миллера.
Цель сейчас - снять барьер, не сделать весь продукт.

Создай минимальный Expo/React Native план:
- один экран
- одна кнопка
- одно действие
- один критерий "готово"
- один способ проверить на устройстве или эмуляторе

Учти:
- текущий стек проекта
- где живет API
- какие ENV нужны
- какие данные нельзя хранить на устройстве
- что должно остаться на вебе

Файл плана: plans/YYYY-MM-DD-mobile-mvp.md
Код не пиши.
```

## Промпт 3: запустить мобильный MVP

```text
Выполни только первую фазу mobile MVP из plans/YYYY-MM-DD-mobile-mvp.md.

Правила:
1. Используй Expo, если это подходит проекту.
2. Не переписывай web.
3. Один экран, одна кнопка, одно действие.
4. Добавь понятную команду запуска.
5. Проверь, что проект стартует.
6. Если нужен dev server, дай URL/команду.
7. Не добавляй auth, payments, push или сложную навигацию без отдельного плана.

В конце покажи, что изменено и как проверить.
```

## Промпт 4: следующие 6 блоков

```text
Mobile MVP запущен.

Составь следующие 6 маленьких блоков развития.
Каждый блок:
- 1 экран или 1 действие
- понятный критерий готовности
- проверка на устройстве
- риск
- что не делать

Не объединяй блоки в большой релиз.
```

## Готовность

Шаг готов, когда мобильная ветка либо честно отложена, либо имеет минимальный Expo-план с одним экраном, одной кнопкой, одним действием и проверяемым запуском.
