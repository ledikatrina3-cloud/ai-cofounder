# Артемий Миллер шаг 13: Оркестратор и фазовая реализация

## Зачем

Большую фичу нельзя отдавать в одно большое "сделай". У Миллера есть оркестратор: он держит план, выдаёт промпты фаз, проверяет результат и отмечает статусы. Исполнитель пишет код только в рамках текущей фазы.

В Codex это можно делать в одном треде через явные этапы или в нескольких тредах: один как оркестратор, отдельные для фаз.

## Роль оркестратора

Оркестратор:
- читает `AGENTS.md`, `architecture/`, план
- не пишет код
- генерирует промпт фазы
- проверяет diff
- обновляет статус `[ ] -> [WIP] -> [x]`
- готовит следующий промпт

## Промпт 1: запустить оркестратор

```text
Прочитай:
- AGENTS.md
- architecture/
- plans/YYYY-MM-DD-<имя>.md

Твоя роль: ОРКЕСТРАТОР.

Ты не пишешь код.
Ты:
- держишь полный контекст плана
- генерируешь промпт запуска следующей фазы
- проверяешь работу исполнителя
- ставишь [WIP] / [x] в плане
- пишешь резюме фазы

Сейчас:
1. Проверь, какая первая незавершенная фаза.
2. Поставь ей статус [WIP].
3. Сгенерируй промпт запуска этой фазы для исполнителя.

Промпт фазы должен включать:
- контекст
- цель
- deliverable
- критерий "сделано"
- релевантные файлы
- что НЕ делать
- какие проверки запустить
```

## Промпт 2: исполнитель фазы

```text
Выполни только эту фазу:
<вставь промпт от оркестратора>

Правила:
1. Перед правками прочитай указанные файлы.
2. Если нужен план действий, кратко запиши его в ответе или в план фазы.
3. Делай только deliverable этой фазы.
4. Не начинай соседние фазы.
5. Не деплой.
6. Не делай destructive-команды.
7. Если нужно писать файлы, используй обычный Codex-процесс: сначала понять, потом правка, потом проверка.
8. В конце дай:
   - что изменено
   - какие файлы тронуты
   - какие проверки запущены
   - что осталось
```

## Промпт 3: вернуть результат оркестратору

```text
Фаза N сделана.

Diff / список изменений:
<вставь git diff или описание измененных файлов>

Проверь:
1. Сходится ли результат с критерием фазы.
2. Не нарушены ли правила из AGENTS.md.
3. Не нарушены ли нерушимые правила из architecture/03-данные/правила-нерушимые.md.
4. Не появился ли код для кода.
5. Что упущено.

Если всё ок:
- поставь фазу [x]
- напиши резюме фазы в план
- сгенерируй промпт следующей фазы

Если не ок:
- не ставь [x]
- дай точечный промпт на исправление
```

## Как не потерять контекст

Если контекст переполнен:

```text
Я хочу продолжить эту задачу в соседнем Codex-треде.
Напиши полный промпт для нового треда, чтобы он продолжил работу без потери смысла.
Включи:
- цель проекта
- текущий план
- статус фаз
- что уже сделано
- какие файлы читать
- что делать следующим
- чего не делать
```

## Готовность

Шаг готов, когда первая фаза реализована, проверена оркестратором и отмечена в плане.
