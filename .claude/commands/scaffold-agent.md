---
description: Создать нового самодостаточного агента в agents/<id>/ из шаблона
argument-hint: <agent-id>
---

Ты помогаешь фаундеру создать НОВОГО агента в этом репозитории AI-Cofounder.
Агент — это самодостаточная папка `agents/<id>/` (см. docs/AGENTS.md).

Запрошенный id агента: **$1** (если пусто — спроси kebab-case id, напр. `daily-revenue`).

Выполни по шагам, по одному вопросу за раз (используй AskUserQuestion):

1. **id и уникальность.** Проверь, что id в kebab-case и что `agents/$1/` ещё не существует
   и id не занят в `routines/` (legacy). Если занят — попроси другой.

2. **Идентичность.** Спроси: displayName (имя «сотрудника», напр. «Финансист»), короткую
   роль (одна строка), emoji-avatar. 

3. **Модель.** Спроси: `opus` (дорогая, для сложного), `sonnet` (рутина, дефолт) или
   `haiku` (дёшево, простые фильтры). Подскажи стоимость на словах.

4. **Что делает.** Спроси свободным текстом, что агент должен делать, и собери из этого
   `prompt.md` (полные пошаговые инструкции — это «системник» агента).

5. **Доступы (permissions.yml).** Покажи список реальных tools из `src/routines/tool-registry.ts`
   (НЕ выдумывай имена — прочитай файл). Спроси, какие нужны (по умолчанию — только
   `report.send`). Если нужен Bash — спроси префиксы команд и предупреди, что
   pipe/redirect/`&&`/backtick запрещены всегда. Если агент читает секреты из Keychain —
   перечисли их в `secrets:`.

6. **Расписание.** `manual` (запуск руками) или cron-выражение. Проверь cron через
   валидатор (можно `pnpm exec tsx -e` с `validateTrigger`, либо просто формат 5/6 полей).

7. **Вывод.** `telegram` | `journal` | `both`.

8. **Кросс-проект? (advanced, по умолчанию НЕТ).** Только если агент должен работать над
   ВНЕШНИМ репозиторием — создай `agents/$1/target.yml` с `cwd: <абсолютный путь>`.
   По умолчанию агент self-contained и target.yml НЕ создаётся.

Затем СОЗДАЙ файлы из `templates/agent/` (AGENT.md, prompt.md, permissions.yml), подставив
значения вместо `{{...}}`-плейсхолдеров. `enabled` оставь `false` (включит фаундер после проверки).

9. **Проверь, что папка валидна.** Загрузи её через парсер — например:
   `pnpm exec tsx -e "import('./src/routines/agent-loader.js').then(m=>m.parseAgentFolder(process.cwd()+'/agents/$1').then(r=>console.log('OK',r.id,r.model,r.outputType)))"`
   Если падает — почини AGENT.md/permissions.yml и повтори. НИКОГДА не оставляй
   непарсящуюся папку.

10. Напечатай чеклист: что создано, как включить (`enabled: true` + при cron —
    переустановить launchd-плист), и как проверить. ВАЖНО: реальная проверка
    свежесозданного агента — это parse/dry-run из шага 9 (агент остаётся
    `enabled: false`). `pnpm dev:run <id>` работать НЕ будет, пока агент выключен:
    диспетчер молча пропускает disabled-агентов, и запуск окажется no-op. Чтобы
    реально прогнать его руками, сперва поставь `enabled: true`.

Правила: только дефис, не длинное тире. Не включай агента (`enabled: true`) без явного
согласия фаундера. Не коммить и не пушь — это решает фаундер.
