# Единый редакционный контур

## Проблема

Writer получает пересекающиеся указания из большого prompt, `rules.md`, skill,
voice-файлов, mastery и QA. Требования к естественному языку, разнообразию и
выбранным приемам живой подачи повторяются в нескольких местах. Агент научился
формально ставить `PASS`, но последние статьи повторяют один каркас: рабочая
сцена, диагностическая проверка, вопросительные H2, маленький пилот и вывод для
руководителя.

Проверка голоса сейчас является самооценкой writer. Проверка разнообразия ловит
отдельные слова и категории, но пропускает одинаковую драматургию. Mastery и
reference-блоги перечисляются в research/QA, однако их влияние на решения текста
не доказывается.

## Цель

Сделать один переиспользуемый редакционный маршрут, в котором голос, мастерство,
референсы и отличие от последних статей реально влияют на черновик, а новая
правка заменяет соответствующее правило в одном источнике истины вместо
добавления еще одного блока.

## Источники

- Голос Екатерины: `ai-clone/voice/` и наблюдаемые приемы живой подачи,
  вдохновленные публичной манерой Татьяны Мужицкой. Используются только приемы:
  разговорная интонация, бытовая узнаваемость, психологическая точность,
  неожиданный поворот, короткая реплика, уместная самоирония и тепло без
  назидания. Авторский голос, узнаваемые фразы и личные истории не копируются.
- Mastery: `mastery/INDEX.md`, профильный слой, copywriting и redaktor. Метод
  считается использованным только при наличии решения до драфта и конкретного
  изменения после драфта.
- Reference-блоги: `org/reference-blogs.md` и публичный Telegram preview
  `https://t.me/s/findir_pro`. Из них берутся тематические вопросы, типы заходов,
  профессиональные противоречия, формы объяснения и практические детали, но не
  фразы для копирования.
- Последние готовые статьи: фактический корпус для сравнения H1, lead,
  композиции, сцены, практического блока и финала.

## Архитектура

### 1. Один источник истины

Создается `org/article-editorial-playbook.md`. В нем живут только редакционные
правила: голос, естественная фраза, способы использовать mastery и референсы,
вариативность композиции и критерии независимой редактуры.

`agents/article-writer/prompt.md` остается коротким оркестратором стадий.
`agents/article-writer/rules.md` содержит только жесткие ограничения публикации,
безопасности и фактов. `skills/article-writing/SKILL.md` содержит только точку
входа и команды. Тексты правил между ними не копируются.

### 2. Редакционный context packet

До драфта детерминированный скрипт создает
`content/<slug>.editorial-context.json`:

- fingerprints последних пяти статей;
- долю вопросительных H2 и повторяющиеся синтаксические формулы H1;
- использованные сцены, композиции, практические блоки и финальные ходы;
- реально открытые reference URL и извлеченные редакционные паттерны;
- выбранные mastery-файлы, методы и планируемое применение;
- три существенно разные кандидатные композиции.

Writer не начинает полный текст, пока packet не прошел контрактную проверку.

### 3. Разные композиции, а не перестановка заголовков

Кандидаты обязаны различаться по нарративной форме. Доступные формы не являются
шаблоном и ротируются по корпусу: разбор решения, профессиональный спор,
последовательность вопросов собственника, история одного рабочего дня, разбор
цифр или документа, FAQ, сравнение двух подходов, ошибка мышления, кейс без
выдуманных результатов.

Hard gate отклоняет материал, если повторяются формула H1, вопросительный каркас
H2, последовательность смысловых блоков, практический артефакт или финальный ход.

### 4. Mastery как решение

До драфта writer записывает для каждого выбранного метода:

- какую проблему текста он решает;
- где будет применен;
- какой вариант отвергнут благодаря методу.

После драфта независимый редактор указывает конкретные строки до и после. Список
прочитанных файлов без наблюдаемого влияния считается провалом.

### 5. Независимый редактор внутри writer run

Новый видимый агент не добавляется. Writer запускает отдельный редакторский
субагент в чистом контексте. Он не видит самооценку writer и проверяет:

- можно ли произнести каждую спорную фразу в обычном разговоре;
- есть ли голос Екатерины и выбранные приемы живой подачи;
- нет ли подражания конкретному автору;
- отличается ли композиция от последних материалов;
- повлияли ли mastery и референсы на текст.

Редактор обязан вернуть найденные проблемы и diff исправлений. Пустой
`PASS` запрещен. Финальный writer повторно прогоняет детерминированные проверки.

## Изменение правил

Любая следующая правка голоса меняет один playbook и его тест. Если изменение
требует править одинаковый текст в нескольких runtime-файлах, архитектурный тест
должен падать. Старые дубли удаляются в рамках миграции.

## Проверка результата

- контрактный тест подтверждает единственный editorial source of truth;
- fixture-тест отклоняет корпус с одинаковыми H1 и вопросительными H2;
- fixture-тест отклоняет фиктивное mastery evidence без решений до/после;
- integration-тест подтверждает фактическое открытие обычных блогов и Telegram
  preview;
- независимый редактор не может вернуть голосовой `PASS` без issues/revisions;
- три пробные статьи проходят ручную приемку пользователем отдельно по голосу,
  естественности фраз и композиционному отличию.

## Не делаем

- не добавляем четвертого видимого агента;
- не копируем стиль, фразы или личные истории Татьяны Мужицкой;
- не превращаем канал `findir_pro` в единственный источник тем;
- не добавляем новый блок поверх старого prompt без удаления дублей;
- не считаем наличие пути к mastery доказательством применения метода.
